Much faster rebuilds, editing while a rebuild runs, and smooth frames in large documents.

## Downloads

| Platform | File |
|---|---|
| Linux x86_64 (glibc 2.35+: Ubuntu 22.04, Debian 12, Fedora 36 or newer) | `cadrs-v0.2.3-x86_64-linux.tar.gz` |
| Windows x86_64 (Windows 10 or 11) | `cadrs-v0.2.3-x86_64-windows.zip` |
| macOS 11 or newer, Apple silicon and Intel | `cadrs-v0.2.3-universal-macos.dmg` |
| A browser with WebGPU, such as Chrome or Edge | <https://cadrs.net/app/>, or `cadrs-v0.2.3-web.tar.gz` to serve yourself |

The Linux and Windows archives hold the executable, its `libraries/` folder (the built-in symbols, footprints and 3D models), the README and the licenses. Nothing needs installing: unpack it and run `cadrs` (Linux) or `cadrs.exe` (Windows), keeping `libraries/` beside it. `SHA256SUMS.txt` has the files' checksums.

On macOS, open the `.dmg` and drag cadrs to Applications. The app isn't signed with an Apple Developer ID yet, so the first time macOS won't open it: right-click cadrs in Applications and choose **Open**, then **Open** again (on macOS 15 and later, open it once, then choose **Open Anyway** in System Settings › Privacy & Security). Updates on macOS are downloaded from the release page and dragged over the old app.

On Linux, the app needs a Vulkan-capable GPU driver, and ALSA and udev (present on desktop distributions). The Windows build isn't code-signed, so SmartScreen may warn the first time: choose **More info › Run anyway**.

Documents are saved in `~/.local/share/cadrs/` on Linux, `%APPDATA%\cadrs\` on Windows and `~/Library/Application Support/cadrs/` on macOS.

## What's new since v0.2.2

- **Faster rebuilds** (#172). pi7zoll-gehäuse's Part Studio 1 rebuilds in 6.5 s, where it took 39.5 s, with the same parts:
  - A fillet, chamfer, shell, draft, split or direct edit of several parts works on them side by side.
  - Booleans, fillets and spline profiles skip a great deal of work that couldn't change their result.
- **Editing while a rebuild runs** (#172):
  - A dialog's ✓ answers at once. It stops the rebuild and rebuilds only up to its feature.
  - Opening a fillet, chamfer or other such dialog during a rebuild no longer freezes the window until the rebuild is done.
- **Smooth frames in large documents** (#173). With vsync off, a house of 1,677 features and 629 parts draws at over 200 frames a second:
  - Long feature and part lists build only the rows near what they show.
  - Icons, part edges, the view cube and the panels do no work on a frame where nothing about them changed.
  - Uploads to the graphics card go through system memory, which is much faster with Vulkan on a computer without Resizable BAR.
- **Preferences › Interface › Display › Vertical sync**, on by default. Turned off, cadrs draws frames as fast as it can make them.
- **The MCP server:** `set_rollback` moves a Part Studio's rollback bar, `show_feature` scrolls the feature list to a feature, `get_ui_layout` lists where the UI's parts are on screen, `set_preferences` sets vertical sync, and `get_frame_stats` takes how many of the slowest systems to list.
- cadrs now runs on Bevy 0.20.1 and wgpu 30.

cadrs is an independent project.
